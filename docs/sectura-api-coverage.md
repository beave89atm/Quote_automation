# Sectura API coverage

This map lists every Sectura step the quote push performs today, then the matching operation in the attached OpenAPI files. v0 is the deprecated REST API (`SecturaFAB REST API 0.0`). v1 is `SecturaFAB REST API 1.0` and includes `/api/v1/quoteOnline`. v2 is `SecturaFAB REST API 2.0`, the file that calls itself the officially supported API. None of the three files were checked against a live host.

Coverage words mean:

- **full** — the spec operation matches the call the app makes.
- **partial** — an operation covers only part of the step. The note says what is missing.
- **no API equivalent** — no operation in v0, v1, or v2 matches this step.
- **unclear** — a nearby operation exists, but the spec does not say whether it is the same step.

The word Finishing in v1 is a `ProductionCodeViewModel.SequenceType` value (`Initial`, `Primary`, `SecondaryPrep`, `Secondary`, `Other`, `Assembly`, `Finishing`, `Shipping`). It is not the website Finish button.

## Auth

None of the three specs declare `securityDefinitions`, `securitySchemes`, a root `security` block, OAuth grants (`client_credentials`, `password`, or any other), or per-operation scopes. No operation lists a required scope.

v1 has `GET /api/v1/auth/claims` (`AuthAPI_GetClaims`). The spec says the response is an object and does not name claims or scopes.

v2 marks several quote routes with a 401 response. `GET /api/v2/test` (`TestAPI_TestAuthenticated`) returns 204 or 401. `GET /api/v2/test/ping` (`TestAPI_TestAnonymous`) returns 204 and has no 401. The spec does not say which grant unlocks the authenticated route.

The app, in `secturafab/auth.py`, posts form fields to the configured token URL. `fetch_client_credentials_token` sends `grant_type=client_credentials` with client id and secret. `fetch_password_token` sends `grant_type=password` with username and password. `fetch_access_token` uses client credentials when a client id and secret are set, and otherwise uses the password grant. That token URL and those grants are not in these specs.

Website writes use a signed-in browser session (cookie plus anti-forgery on the quote editor). A 302 to `/Account/Login` is treated as a failed session. The specs do not describe that cookie session.

## Gaps

STEP and CAD import through the website is still missing from the API. `POST /CadImport/UploadItem_DXFFiles`, `POST /part/create`, and the CadImport classify calls (`Data`, `CADData`, `SetUnits`, `SetPartMode`, `UpdateItemType`, `UpdateData`) have no matching operation. v0 `POST /api/part/create/{id}` is a different contract (id only, empty 204). The API can create one flat CAD line: v1 `QuoteOnlineAPI_QuickAddItem_CAD` and v2 `QuoteAPI_AddCadItem`. Both limit the file to DXF, DWG, NC1, or vector PDF. Neither spec mentions STEP or exploding an assembly into children.

Finish and reprice are missing. `POST /Quote/AddItem_DXFFiles`, `POST /Quote/AddItem_PDFFiles`, and `POST /Quote/AddItem_Linear` are the calls that run the shop calculators and write Primary Costs. No spec operation is named Finish, and none describe that calculator. Nearby calls do other jobs: v0 `QuoteAPI_RecalcWeight` recalculates weight from density, and v1 `POST /api/v1/quote/ResetCosts/{startDate}/{updateCost}` `QuoteAPI_ResetCosts` loads cost from the quote or from older quotes. `addplate` and `addLinear` add a line. They are not Finish.

Weldment and assembly structure is missing as its own step. There is no copy/move, weldment, or assembly endpoint. v1 items have `AssemblyID` and related fields, and the app sends them on `POST /api/v1/quote`. The spec does not say that save builds the tree the website builds with `POST /Quote/CopyMoveItemToAssembly`. v2 returns `AssemblyId` on a quote item and has no request body that sets it. Weld and profile calculator rows can ride along inside `OperationCostList` on that same v1 save. There is still no Add Operation endpoint, and the operation type enum does not name weld or laser.

Other website steps with no matching operation: the Image Files upload widget (v0 generic attachment upload is undescribed), hole features (`/Quote/AddFeature`), PDF internal geometry, perimeter-from-size, and linear renest at a stock length (`/Nest/RenestLinear`). Creating nest tasks does exist (`NestAPI_NestQuote`).

## Questions for Sectura

1. Can a service account import a STEP file and explode it into child parts through the API, the way the website does with CAD Files upload and `POST /part/create`? The attached specs only accept DXF, DWG, NC1, or vector PDF on quickAddCAD and v2 add-cad-item.
2. Is there an API for website Finish (`AddItem_DXFFiles`, `AddItem_PDFFiles`, `AddItem_Linear`) that runs the laser or saw calculators and writes Primary Costs?
3. Is there an API to reprice a quote after items or operations change? v0 recalcWeight only updates weight, and v1 ResetCosts loads costs from old quotes. Neither is described as Finish.
4. How should a client build a weldment (assembly parent plus children) through the API? v1 items have `AssemblyID`, and v2 items return `AssemblyId`, but neither spec has a copy/move or weldment operation.
5. `client_credentials` works for this agent. The password grant returns `invalid_grant`. Which grant, client, and scopes should a long-running service account use? These specs do not list grants or scopes.
6. Many website routes redirect to `/Account/Login` without a browser cookie, and the quote editor also needs anti-forgery. Which of the steps above are supposed to stay on that cookie session, and which should move to the token API?
7. Is there a test or sandbox tenant where an agent can create quotes and throw them away without touching live customer quotes?
8. Does `POST /api/v1/quote` with `AssemblyID` and `OperationCostList` persist a weldment and its weld or profile operations, or does that save only store fields while Finish and Copy/Move remain website-only?
